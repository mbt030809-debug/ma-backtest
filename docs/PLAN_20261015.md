# Virtuoso Schematic → PrimeSim 실행/프로빙 도구 개발 플랜 (2026-10-15)

## 1. 목표

- Virtuoso 스케매틱 테스트벤치(lib/cell/view)를 Python에서 불러옴
- 스케매틱에 쓰인 **설계 변수**를 자동 추출 → 값 편집
- 넷리스트 생성 → PrimeSim 덱 조립 → `primesim_sub -spice`로 실행
- Virtuoso 스케매틱에서 **넷/핀 클릭 → 전압·전류 프로브 등록**
- 결과 파형 확인

## 2. 확정 전제

| 항목 | 값 |
|---|---|
| Virtuoso | IC 6.1.8 |
| ADE | **사용 안 함** → 변수·분석·모델은 이 도구가 직접 관리 |
| 시뮬레이터 | PrimeSim SPICE, `primesim_sub -spice <deck>` |
| Python | 3.11 |

## 3. 아키텍처

```
┌──────────── Virtuoso 6.1.8 ────────────┐        ┌──────────── Python 3.11 앱 ────────────┐
│ skillbridge 서버 (pyStartServer)       │◀──IPC──│ vbridge     : 연결/호출                  │
│ pb_probe.il : 단축키 → 선택 큐 적재     │        │ tb_loader   : 계층 탐색, 변수 추출       │
│              하이라이트 표시            │        │ probe       : 큐 폴링, 이름 매핑         │
└────────────────────────────────────────┘        │ netlister   : si 배치 넷리스팅           │
                                                  │ deck_builder: PrimeSim 덱 생성           │
        si -batch (넷리스트)  ◀───────────────────│ runner      : primesim_sub 실행/감시     │
        primesim_sub -spice   ◀───────────────────│ waveform    : 결과 파싱/플롯             │
                                                  │ project     : YAML 저장/복원             │
                                                  │ gui         : PyQt 화면                  │
                                                  └─────────────────────────────────────────┘
```

### 데이터 흐름

1. 사용자: lib/cell/view 선택
2. `tb_loader`: 계층 순회 → 인스턴스 파라미터 → 변수 목록
3. 사용자: 변수 값·분석·모델·코너 입력 (YAML로 저장)
4. 사용자: Virtuoso에서 넷/핀 선택 후 단축키 → 프로브 목록에 추가
5. `netlister` → 넷리스트 + 이름 매핑 파일
6. `deck_builder` → `top.sp` (include + .param + 분석 + .probe)
7. `runner` → `primesim_sub -spice top.sp` → 종료 감지
8. `waveform` → 파형 표시

## 4. 모듈 상세 설계

### 4.1 vbridge (Virtuoso 연결)

- 라이브러리: `skillbridge` (pip, 오프라인 wheel 설치 가능)
- Virtuoso CIW: `load("<skillbridge>/server/python_server.il")` → `pyStartServer`
- 기능
  - `connect(id=None, timeout)` / 버전 확인 `getVersion()`
  - SKILL 원문 실행 헬퍼 `ws['evalstring']`
  - 끊김 감지·재연결
- `.cdsinit`에 자동 로드 스니펫 제공

### 4.2 tb_loader (테스트벤치·변수 추출)

- `dbOpenCellViewByType(lib cell "schematic" "" "r")`
- 계층 순회
  - 각 인스턴스 master가 schematic 보유 시 하강 (view list: `schematic` 우선, stop list: `spectre`, `hspiceD`, `symbol`)
  - 결과: 계층 트리 `{path: [inst...]}` (프로브 UI·이름 매핑에 재사용)
- 변수 추출
  - 인스턴스 CDF 파라미터 값 문자열 수집 (`cdfGetInstCDF(inst)~>parameters`)
  - 수식 토크나이저로 식별자 추출
  - 제외: 숫자(+단위 접미사 `u n p f k meg`), 내장 함수(`sqrt exp log min max abs` 등), `pPar()/iPar()/atPar()` 인자, `temp`
  - 결과: `{var: [사용 위치 inst.param ...]}`
- 기본값 출처 (우선순위)
  1. 프로젝트 YAML에 저장된 값
  2. cellview 속성에 저장된 변수(있을 경우; Phase 0에서 확인)
  3. 미정 → GUI에서 필수 입력 표시
- 테스트벤치 내 소스(vsource, isource 등)도 목록화 → 분석 설정 시 참고

### 4.3 netlister (넷리스트 생성)

- ADE 없이 `si` 배치 사용
  - 실행 디렉터리 `runs/<cell>_<YYYYMMDD_HHMMSS>/netlist/`
  - `si.env` 자동 생성: `simLibName`, `simCellName`, `simViewName`, `simSimulator`, `simViewList`, `simStopList`, `simNetlistHier = t`
  - 명령: `si <dir> -batch -command nl`
- 넷리스트 형식 두 경로 (Phase 0에서 확정)
  - A안 `hspiceD` → HSPICE 문법, PrimeSim SPICE 기본 호환 (**1순위**)
  - B안 `spectre` → PrimeSim의 Spectre 문법 지원 여부·라이선스 확인 필요
- 산출물
  - 넷리스트 본문 (top-level 소스·서브서킷 포함)
  - `ihnl/*/map` 등 이름 매핑 파일 → probe 이름 변환에 사용
- 넷리스트 실패 시 `si.log` 에러 요약 표시

### 4.4 deck_builder (PrimeSim 덱)

- Jinja2 템플릿 → `top.sp`

```spice
* auto-generated <lib>/<cell> <timestamp>
.option post=2 probe=1 <사용자 옵션>
.lib '<model_file>' <corner>
.temp <temp>
.param vdd=1.8 wn=1u ...          $ 추출 변수
.include './netlist/netlist'
.tran 1p 10n                      $ 분석
.probe tran v(xi0.net12) i1(xi0.xm3)
.end
```

- 분석: `.tran / .dc / .ac / .op` 입력 폼
- 코너/스윕: 1차는 단일 실행, 2차에 `.alter` 또는 다중 run 디렉터리
- 덱 생성 전 검증: 미정 변수, 존재하지 않는 프로브 노드 경고

### 4.5 runner (실행/감시)

- `subprocess.Popen(["primesim_sub", "-spice", "top.sp", ...], cwd=run_dir)`
- `primesim_sub`가 **잡 제출 래퍼(LSF 등)** 일 가능성 → 두 모드 지원
  - 동기: 프로세스 종료 = 시뮬 종료
  - 비동기: 잡 ID 파싱 → 로그(`*.lis`/`*.log`) 끝 문자열(`job concluded` 등)·잡 상태 폴링
- 로그 실시간 표시, 에러·경고 패턴 하이라이트
- 실행 중단(잡 kill) 지원
- 각 run 디렉터리에 `run_info.yaml` (변수·프로브·명령·시간) 저장 → 재현성

### 4.6 probe (클릭 프로빙)

- 전제: skillbridge는 **Python → Virtuoso 단방향 호출**만 가능 → Virtuoso가 Python에 직접 알릴 수 없음
  - 해결: Virtuoso 쪽 SKILL 전역 큐에 클릭 결과 적재 → Python이 주기적으로 꺼내감(폴링)
- 입력 방식 2가지
  - A. 단축키: 평소처럼 넷 선택 → 단축키
  - B. 프로브 모드: Python의 [프로브 모드] 버튼 → SKILL `enterPoint(?doneProc ...)` 실행 → 스케매틱 클릭 지점의 객체 판별 → 큐 적재 (Esc까지 반복)
- Virtuoso 측 `pb_probe.il`
  - 단축키 (예: `Ctrl+Shift+P` 전압, `Ctrl+Shift+I` 전류) → `pbProbeSelected("V"|"I")`
  - `geGetSelSet()`으로 선택 객체 판별
    - wire/label/net → 넷 이름
    - instTerm(핀) → 인스턴스 + 터미널
    - 인스턴스 → 전체 터미널 전류
  - 현재 계층 경로: `geGetHierMemInst(window)` (descend 상태 반영)
  - 결과를 SKILL 전역 큐에 적재 + 하이라이트 표시 (`geCreateHilightSet`)
- Python 측
  - 300 ms 주기로 큐 폴링 (`pbPopQueue()`)
  - 이름 변환: 스케매틱 경로 `/I0/net12` → 넷리스트 `xi0.net12`
    - si 매핑 파일 우선, 없으면 규칙(서브서킷 `x` 접두, 소문자, 버스 `<0>` → 넷리스터 규칙)
  - 전류 표현
    - 소자 터미널: `i1()~i4()` (MOS d/g/s/b → 1/2/3/4, 소자별 핀 순서 테이블)
    - 서브서킷 핀: `isub(xi0.pin)`
    - 전압원: `i(v0)`
- 프로브 목록: 추가/삭제/별칭, YAML 저장

### 4.7 waveform (결과)

- 1순위: `.option post=2` (ASCII) → 자체 파서 → numpy
- 2순위: 바이너리 tr0 파서
- FSDB만 나오는 경우: Custom WaveView(`wv`) 실행 연동으로 대체
- 플롯: pyqtgraph (다중 신호, 커서, 축 단위)
- CSV 내보내기

### 4.8 project (설정 저장)

- `projects/<lib>_<cell>.yaml`

```yaml
testbench: {lib: myLib, cell: tb_amp, view: schematic}
netlist: {format: hspiceD, view_list: [...], stop_list: [...]}
models: [{file: /pdk/models.lib, corner: tt}]
temp: 27
variables: {vdd: 1.8, wn: 1u}
analyses: [{type: tran, step: 1p, stop: 10n}]
probes: [{kind: V, sch: /I0/net12, net: xi0.net12, alias: vout}]
options: {post: 2}
sim_cmd: [primesim_sub, -spice]
```

### 4.9 gui

- PyQt5 (서버 설치 여부 Phase 0 확인, 없으면 CLI 먼저)

- CLI 병행: `vps load|netlist|run|plot` → 배치·디버깅용
